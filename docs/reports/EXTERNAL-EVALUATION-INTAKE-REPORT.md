> 公开整理版：保留工程方法、实验结果与失败记录；本机路径已泛化，教学和内部协作记录留在本地。原始数据、模型和运行日志不随仓库发布。

## 实际数量与来源

60故事、360用户轮，10类各6故事；每故事6轮、2–3个会话。30推荐任务、每任务8个商品及评分，共240商品/240评分。上述数量由独立读取实际JSONL复算，未采信生成器的PASS字符串。最终requested_shape_checks全部满足。

用户原始输入在data/evaluation/incoming；封存于artifacts/external_evaluation_audit/20261023-final。manifest保存两原始文件SHA256、审计源码摘要及未划分/零API声明；generator-check-report.md与generator-source保存原报告和六文件。已验证封存字节摘要与原输入相同。不能因来自另一个AI就称独立人工gold或真实用户数据，生成模型族/过程独立性尚未核实。

## 新增审计能力

external_evaluation.py独立复算长期状态，核对证据引用只指向已发生轮、人物长期归属、撤销/删除目标、删除后旧证据复用、重复事实与ID、任务引用/请求及评分集合。数值有单位/类型检查，支持price/weight/battery/screen尺寸/storage以及screen_type枚举。当前请求同属性覆盖长期要求，人物会话信息不跨会话复制；缺少请求生命周期标识或语义存在歧义时只提出review，不擅自补标签。

audit_external_evaluation.py拒绝重复JSON键、非有限数字/超限输入和覆盖已有产物目录。输出原始字节、摘要与审计结果，不调用模型，不改原数据。结构检查不能证明自然语言含义、证据蕴含或全部标注正确，也不是完整通用JSON Schema验证器。

可复现命令（新输出目录必须不存在）：

```sh
rtk proxy env UV_CACHE_DIR=.uv-cache uv run --offline --locked --extra ml --extra api python scripts/audit_external_evaluation.py --stories data/evaluation/incoming/stories.jsonl --tasks data/evaluation/incoming/recommendation_tasks.jsonl --output-dir artifacts/external_evaluation_audit/new-run
```

退出0表示此检查器无已发现问题，1表示审计发现问题/待复核，2表示入口错误；不将0解释为语义gold完全正确。

## 发现的问题

最终13条机器发现：1条结构/操作契约错误、12条待复核（11条同品牌分差，1条当前约束）。额外人工语义检查和位置相关性不包含在这13条计数中。

1. ST002/T6将长期dislike直接改成exclude，但没有retract旧态度，与生成器报告声明的修订格式不符。原话“帮我挑一台吧，三星就先别考虑了”也更适合本次排除，不应据此自动升级长期排除。建议新派生版本保留长期dislike、把本次exclude放请求范围；原始版本不改。
2. RT021同时提供长期预算<=2500和本次预算<=4000，交集会错误恢复2500限制。T4明确本次放宽仍有效、T6继续同一请求，当前应使用4000并保持长期2500不变。原格式没有请求ID/结束标识，不能把每轮空request_only直接当作已清除本次要求；转换时须明确生命周期。
3. RT001、008、013、019、020、025、026、037、049、055、056共11任务，同品牌且合格商品因价格/重量/续航等被赋不同分，但作用域标签未提供相应属性偏好。比如RT001只有小米品牌偏好，却以“偏重”“价格与手感均衡”区分小米商品。它们不是自动判错项：可能遗漏属性依据，也可能需要同品牌并列。须复核理由，不能以作者偏好的“好产品”替代用户表达。
4. 商品位置明显带标签信息：原输入位置1平均原始relevance=2.70，位置8为0.90。正式实验要预先固定候选随机顺序及无序号语义的ID映射，所有组共用，保留原ID回映射。不能让候选输入顺序成为答案捷径。
5. ST048/T2“护眼模式必须有”未形成属性gold，现有商品也没有对应字段；这是覆盖/标注缺口。不能声称已覆盖所有硬约束。
6. 9轮gold要求澄清，其中ST034/T1“都行，你看着办”、ST035/T1“还行吧”没有实际待执行购买操作；ST036/T1“预算三千，别超”也未出现他人主体。必须追问并非唯一合理动作，存在把普通聊天变成盘问的风险。后续独立复核应允许合理无操作回答/暂不写入，不能以后一轮脚本补充信息为理由认定前一轮必须问。

6条商品评分同时eligible=false、raw relevance>0，保留为合法的两个维度，不强迫改成0。后续排名效用应使用eligible_only的gain（不合格商品有效gain为0），同时单独报告硬约束违例；否则NDCG可能奖励不合格商品。
