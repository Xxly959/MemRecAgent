## 正式接口

`MemoryProductRecommender.recommend`和`resolve_recommendation`增加可信布尔`use_long_term_memory`，默认True。False只跳过长期偏好读取，仍使用同一个存储的删除水位、用途许可和发布快照；当前请求与会话偏好保持相同。拒绝None、数字和字符串等隐式真假值。True不能绕过用户关闭个性化的持久许可。

Python只读推荐工具允许绑定请求携带该开关与`normalisation`；模型仍只能调用空参数工具，不能改这些实验配置。发布凭据绑定完整请求字节，修改开关后旧凭据不能交付。

`run_ranking_ablation`四组统一使用这个正式接口，去掉内部私有关闭视图。G00热门、G10热门加长期记忆、G01已有算法、G11算法加长期记忆；四组配置控制开关，不允许请求自行覆盖。算法是否真正具有活跃用户向量仍单独报告。

## 从空库到真实Pi工具的工程故事

新增固定客户端故事：空库中收到本人长期排除品牌A、喜欢品牌B的合成原话，经实际双阶段宿主提交后，换会话由真实Pi循环调用Python工具执行四组。另一个故事让两段客户端都返回非法JSON，实际磁盘无新增记录；后续四组继续使用这个失败留下的空状态，不按标准答案补库。

固定测试向量使算法顺序为A/C/B，热门为A/B/C。成功写入后有记忆的两组均为B/C；失败故事四组分别维持各自基础排序。它验证集成、错误传播和实验开关，不是训练结果、真实用户效果或模型语言理解成绩。

每组实际执行2次固定主模型回调、1次排名工具与1次最终凭据校验，检查ID顺序与无记忆组信号。测试在推荐前后比较实际memory目录所有文件字节；只比较历史trace文件不足以证明磁盘只读，作者已在最终验证前改正该断言。

持久化工程历史位于`artifacts/memory_ablation_pipeline/20261023-increment3a/fixed-committed`与`fixed-invalid`；Node完整日志保留实际Pi八次推荐检查。所有固定客户端HTTP为0。
