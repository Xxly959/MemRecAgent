### 通过与失败的实际含义

Q/T2两模式均保留他人明确prefer与原人物证据，没有因“并非我态度”造本人修订。Q/T3 direct仍引用T3新“我姨妈”，身份ID与T2不同，实际漏激活；analyst最终改用T2原锚点并激活，单列唯一精确检查0/1与1/1。不能仅以显示称呼相同称主体正确，也不以该1例关闭ISS-039。

R整段两模式均通过，负体验原文包含品牌证据、删除后不恢复旧取向，后续三星prefer→exclude形成新修订。P的范围确认current、R的范围确认long_term均完整通过，保持未答之前不写入。

P/T5“这回先给我看看苹果手机，先前的偏好不用改”两模式判consult而非期望的商品推荐请求；false request却附实体/category，旧宿主按非推荐占位忽略，未取得相应推荐激活。topics也用“苹果手机”而非“苹果”，但此失败不仅是原始引用粒度。

Q/T4本次要求看看苹果并保留旧限制，两模式草案把“保留原来的长期限制”新提为长期exclude，且片段无苹果，被entity_evidence正确拒绝。analyst在草案失败后未进入独立角色，所以39请求；不是供应商错误或预算耗尽。说明输入模板不强制语义正确，也暴露“草案非法时专职角色无机会独立重读”结构限制，登记ISS-050，不应继续无限提示追分。
