## 这次实际做了什么

Python `memory_products.py`复用磁盘JSONL、人物/请求策略及已有ProductService的完整候选基础分。`memory_product_tool.py`绑定可信目录、用户请求与显式商品实体映射，作为单次只读进程；Pi `recommendation-agent.ts`实际调用它，第二轮模型只能给出与回执顺序相同的ID，程序展示可核对分数和来源。发布前新进程核查记忆、用途revision及包/请求/实体映射摘要，变化则不发旧结果。默认CLI离线；显式live才使用环境Key，每轮最多两次HTTP，无重试。

最终回答格式在本增量受到严格约束，是机制接入证据，不代表自由生成问答质量或用户满意度。没有写入真实用户记忆、新训练、下载、依赖变更或推送。

## 一个完整例子

所有手机/品牌与记忆均为显式合成，模型权重来自既有固定测试向量，不是重新训练：

| 商品 | 基础热门分 | 归一化分 | 受控预置本人偏好 | 处理 |
| --- | ---: | ---: | --- | --- |
| A | 10 | 1.0 | 长期明确排除品牌A | 过滤 |
| B | 9 | 0.5 | 无 | 综合0.5 |
| C | 8 | 0.0 | 长期喜欢品牌C | 0+0.75×1=0.75 |

新会话重新打开同一磁盘库，结果应为C、B；空库对照为A、B、C。0.75在测试前固定，未按结果调参。过滤在最终Top-K前执行，归一化范围在记忆过滤前固定。没有把“仅重排旧Top-K”误当完整候选融合，也没有从商品标题猜品牌。

“这次给我看A”临时覆盖旧排除，下一轮无此要求仍排除A；原证据不改。给亲戚推荐只使用亲戚的会话表达。主体不明且与明确旧偏好冲突时询问。人物隔离还必须覆盖协同过滤和已见历史，见下面审查发现。
