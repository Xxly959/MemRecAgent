## 结论与适用范围

**在当前OpenAI兼容接入条件下，继续推荐Pi Agent Core。** 两边都能完成真实工具循环，没有观察到足以支持切换dsh的缓存/正确性收益。选择同时考虑Pi可直接控制的少量领域工具及集成边界，不宣称它在所有场景中更好。

本轮比较Pi Agent Core1.4.0与dsh0.2.1-rc.2的SDK profile；dsh使用其正式llm-pi-ai适配，两边共用已安装pi-ai1.4.0和OpenAI Chat Completions后端。**没有测试dsh原生Messages适配的in-history更新、长上下文压缩或复杂任务能力。** 不能把本轮结果外推为原生dsh没有缓存优势。

### 128个缓存Token差异来自何处

顺序为Pi-a→dsh-a→dsh-b→Pi-b，交换先后以减少单一顺序偏置；仍不能强制清服务端缓存，也没有大量随机重复。Pi-a首调hit=0；其他三个会话首调hit=128。每个会话其余三个请求命中均为256、256、384。因此总差异恰为最早Pi-a首调少128，后续反向配对dsh-b/Pi-b的逐请求hit/miss相同。

这与运行顺序/共同前缀预热相容，是解释性推断，不能证明由某一框架导致。没有稳定差异的证据，不能把53.00%写成dsh缓存能力高于Pi。此前Phase3的81%/85%来自更长的另一组请求，与本次不同，不能比较为缓存退步。

本轮耗时样本极小，且不含进程启动/依赖安装、没有冷启动或压力试验，不据中位数约0.25秒差异判稳定快慢。中继缓冲完整SSE后再交宿主；附带的ttft_ms只是在中继观测到首个生成delta的时间，不是用户界面流式TTFT。

- 精确安装Pi Agent Core/pi-ai1.4.0、dsh0.2.1-rc.2，隔离目录的package-lock保存解析版本/integrity。安装禁用scripts；生产pyproject.toml/uv.lock未改。

- 两边只有catalog_status，模型不能选择路径、用户身份、时刻或命令；未开放shell/图像/工作目录工具，未接记忆或排名。
- 统一系统提示、模型deepseek-flash、当前消息及领域返回；dsh必需的运行目录上下文也显式提供给Pi，使用固定无个人信息的/private/tmp路径。参数、工具声明与用户文本形状经纯假模型对齐。
- 中继只统一temperature=0、thinking=disabled、max_tokens=512，不修改messages/tools；修改前后wire和摘要都记录。第一次真实请求两边forwarded JSON完全一致；后续自由生成的工具ID等可能不同，不能称自由循环全程每字相同。
- 每用户轮最多2物理模型请求、全组最多16；第三次请求在出网前拒绝。API Key只由显式live中继读取，宿主持占位Key，认证headers不保存；只发合成任务。首provider失败停止全部，错误/缺失不缩分母。
