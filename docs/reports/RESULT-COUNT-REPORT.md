## 行为与边界

只在已接受的推荐动作中，用最新实际用户原文识别明确的1至10款/部/台/个/件，支持常见中文及阿拉伯数值、推荐/再给/改为等请求片段和独立数量短句。数量覆盖受信fallback k，但不跨下一用户轮或会话保存；未明确数量时原k1至50接口不变。交互明确数量上限10沿用既有展示规模和512主模型输出预算，不能据此宣称支持50款完整语言输出。

历史购买/明确过去推荐、价格或容量不作本次数量。区间、冲突数量、引用独有、超限以及否定数量没有明确替代时，请用户完整重述；不忽略否定后恰好又返回相同默认数。当前请求动词之前的“看过”“想好了”“不过”等背景不再误吞掉后面的明确数量。

这些是有限句型规则，不是完整语言理解。推荐意图、人物、品类仍由现有分析器负责；复杂组合、比例分配、相对变化、长期默认数量及任意否定/引用不保证正确处理。不能从这里外推出模型整体可靠性。

## 排名与保存

数量歧义在受控commit之前处理，同轮新品牌偏好和预算不会部分保存，若有长期提案会明确提示尚未保存。当前有效数量只改变本次k，不新增记忆字段、输出协议版本、模型调用或融合算法。

已识别数量的原文位置会独立参与长期证据范围检查，模型漏填recommend标志也不能关闭该保护。整句“长期喜欢C，推荐两款”不能原样落长期；可用真实最小稳定分句保存品牌偏好，不裁剪/改写已有证据。这里是已识别片段的可测守卫，不承诺任意临时信息都被发现。

推荐回传可选requested_count、count_evidence（最新turn_id及原文字符区间）。重复同一数量只需一处有效旁证，避免放大工具回执；全部匹配位置仍用于保留范围检查。四组复用已接受query的同一k、预算、人物、来源及nonce，不重做分析或写盘。

Node客户端拒绝非1至10的显式数量及返回条数超过数量。现有ID顺序守卫保持；不足时程序显示“仅找到N款、本次希望M款”，不补造商品。默认k不是用户明确愿望，没有显式数量时不显示虚构的“希望k款”。
