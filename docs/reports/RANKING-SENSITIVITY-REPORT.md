## 如何避免重跑模型和截断重排

原外部开发集只保存 Top-3，直接改这三个商品的分数会遗漏可能上升的候选。此次使用 `artifacts/external_replay/20261024-dev-v1/source-before-calls/` 原源码，隔离导入，并禁用 socket 连接及 DeepSeek 客户端。依次返回当时保存的 267 个原始响应，逐次要求传给分析器的 messages 完全相同；单次 89、双阶段 178，全数吻合。

每模式全部 90 步的动作、错误和记忆状态与原记录一致；15 任务×4组×2模式共 120 个原始组结果的状态、商品 ID、指标及实际策略都复现。恢复的是当时实际接受的请求/人物/约束，不从参考答案补齐错误。新 CLI 的默认 minmax/.75 结果还单独逐项核对原 120 组，同样一致。原运行所有文件摘要未变；新增模型调用为 **0**。

只在原宿主真实 query 存在时，以原排名器导出完整过滤后候选的 minmax/rank 特征；本数据每池8商品，小于完整导出上限50。所有候选齐全后才按新权重重排、截取K。原失败任务导出 error，不生成理想请求。输入包含归一化前分、归一化分、实际偏好信号；参考标签只用于评分。

封存原 inputs 包含全套 split 信息，离线读取后仅选择 dev；预留 test 没有用于排名、评分或模型发送。不能将此描述为“从未读取整份原始文件”。

2种归一化（minmax/rank）×5个权重（0/.25/.5/.75/1），四组，K=3。15个相同开发任务分别来自 direct/analyst，即30个模式-任务观测，不是30名独立用户。每模式主分析10个 provisional 任务、5个场景族；另含5个 review_required 的15任务结果只作次要描述。

各族内部均值、族间等权；相对既定 minmax/.75 使用同族配对1000次 bootstrap，seed20261024。失败效用0且留分母，无可用gain为N/A，不擅自补0。区间是开发集探索性描述，没有多重比较校正，不挑赢家、不改默认或选择测试集配置。权重0仍有长期硬过滤，不能冒充关闭长期记忆。
