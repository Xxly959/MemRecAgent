# 共享草案的真实模型配对控制

> 公开整理版：保留工程方法、实验结果与失败记录；本机路径已泛化，教学和内部协作记录留在本地。原始数据、模型和运行日志不随仓库发布。

2026-10-24首测完成：单次草案18/18、可见草案的最终角色18/18、隐藏草案17/18，
没有显示二次分析优于单次。隐藏分支唯一差异是在空RAM场景额外开始空条件请求，
不能直接等同为推荐错误。这个实验是固定前态的只读候选控制，不是自动写入或Pi推荐效用实验。

## 固定了什么

`compare_shared_draft` 每例实际生成一次草案，同时作为direct结果；
两个最终角色复用同一实际草案、对话、人物上下文及草案选择的同一MemoryView。
system prompt相同，可见分支收到draft/必要时的untrusted_draft，隐藏分支不收到其正文或错误码。
总计每例最多3次实际调用，而非把共享草案在各臂重复累计。

首调前封存78文件，含全部生产Python、实际CLI、锁文件、数据及生成/启动/核验脚本。
seed20261024先打乱案例，再交替两个最终角色顺序，实际各9次先运行。
18对实际请求已逐消息核验：角色system一致，payload除草案通道外一致。
9对view非空、9对为空；view仍依赖草案选择，所以识别的是固定view下直接看草案的影响。
每个响应的模型、用量、阶段、实际消息与请求摘要均保留，默认终端只输出摘要。

## 数据、标签和统计范围

18例来自本助手编写的固定模板，6个场景簇，每簇3个品牌或预算变体。
没有额外API调用生成数据，没有使用原始用户对话；这不等于独立人工标注。
作者已知标签，属于针对规则的合成控制，不能作为真实用户或自然语言分布的可靠性证明。

场景包括他人喜好不投射本人、本次覆盖保留旧排除、撤销长期排除、询问不等于喜欢、
明确未定范围、长期硬预算。需要历史的案例由输入提供已知前态，绝非系统先前自动写出的记忆。
本实验不调用提交接口、不测排名或完整回答。

原始v1与生成器保留；首调前final版本为三例增加“我叔叔/叔叔”两种合法人物锚点，
有父版本摘要和变更日志。没有根据模型输出修改标签。参考候选先独立通过严格解码，
只在评分端投影，不进入模型。允许预先声明的多个合理参考；比较不要求相同证据措辞，
但保留人物原文锚点、意图、请求、断言、线索、未解、确认和两类属性的语义字段。
这种编译保证结构一致，不保证参考语义无争议。

预注册主指标是严格语义投影匹配，主差值blind−visible；按整个场景簇先平均再等权汇总，
1000次整簇bootstrap，取排序样本第25与975项作为描述性区间。
18例不是18个独立用户，只有6个模板簇。失败和未执行保留总分母，中止不报告配对区间。
本组没有另设盲测集，原项目预留test和旧dev均未用于本轮模型调用。

## 唯一差异及业务边界

另两分支为null；请求人物、品牌、极性和所有其他字段都匹配。
按冻结参考仍计17/18，不追改为满分。

将三个已保存响应仅离线解码，调用真实advance_request/bind_constraints/bind_relaxations：
在本例空RAM前态下均无硬约束、无解除、无品牌断言或长期属性修改，
只有blind新建临时请求ID。没有测出推荐效用损失；其他已有条件的场景可能不同，不能泛化为等价。
这是事后机制诊断，未补算“修正准确率”，也未重新调用模型。
