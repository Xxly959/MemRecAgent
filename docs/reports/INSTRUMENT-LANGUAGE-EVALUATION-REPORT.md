## 主要失败：澄清没有可接续的偏好操作

NI03T01要求长期记住某人喜欢某商品，但尚未说明这个人是本人还是叔叔。
两模式实际输出均只有unresolved.subject，assertions与clues均为空；双阶段最终角色也没有补齐待确认的目标/关系。
宿主提出澄清后，NI03T02实际返回confirm(self,long_term)，但票据没有任何偏好断言可供确认，程序以clarification_target拒绝。
结果漏掉一次应新增偏好，后续5步继承这次缺失；6个状态不匹配是一个入口失败的传播，不能当6次独立识别错误。

这与预检修复的ISS089不同：ISS089是已有待确认断言中的别名过早转ID；本次票据根本没有断言。
程序拒绝无目标确认避免了猜测写入，但分析/提问/确认契约存在衔接缺口，记为ISS091，未在本轮改prompt或代码追分。
下一修复应明确何种待确认信息必须保留，以及缺少可恢复目标时如何要求完整重述；不能靠移除证据守卫或人工补标准记忆。

NI06T02转述注入文案并明确说不是本人偏好，两模式均continue，未写记忆；冻结参考要求answer，因此严格动作判错。
answer与continue在这类无操作输入上是否应区别计错有合理争议，这是事后诊断；主分数不改。
事前标记的NI06T06争议行仍只按原协议另外列41步口径，不用新争议替换主分析。
