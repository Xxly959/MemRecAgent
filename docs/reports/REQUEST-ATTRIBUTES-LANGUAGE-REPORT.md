## 新增行为

严格兼容旧schema2。新schema3必须额外包含attribute_request，取null或带operation(start/update/end)、scope=request、Subject、conditions、remove_attributes与用户Quote。每项数值需在最新用户所引原文找到显式阿拉伯/中文值，支持“三千”“两千五”“四千五百”、明确k/万后缀；枚举值须在引用原文出现。拒绝助手证据、旧轮重提、伪造值、模型请求ID/时间及长期scope。仍不能据词面数值匹配证明属性、比较方向、硬软程度、主体和范围语义必然正确。

InteractionPreview只携只读候选；ConversationProductSession预计算RAM状态，原受控commit成功后才接纳。宿主生成新请求ID，update替换同属性方向或明确移除，end结束，不把条件写成长期属性。换受益人不套本人预算，新session不继承；删除/用途变化导致前缀失效时旧属性源Turn快照也失效。未知主体先走现有澄清门控，确认必须绑定真实展示过的问题；预算候选接续原提案并追加实际确认引用，取消不接纳，unclear保留待办。不能借一次确认同时猜两个独立对象，未知属性人物与品牌断言混合时要求完整重述。

属性other通过原人物锚点摘要规则登记，后续分析收到相同known_other_subjects；没有把他人的预算写入本人长期结构。主模型提示明确：new_memory_ids对应品牌记忆，不表示预算已经长期保存；这是提示约束，不是对任意自由回答的形式化证明。

目前支持的是最新轮明确数值或已建立的当前RAM条件。没有提供任意历史指代继承、软属性评分、单位自动换算和长期属性保存；不能将“以后都这样”降级为本次保存来冒充长期支持。

## 首测失败与修复

两次分析都将“这次选购结束，先不买了”输出为unrelated＋attribute_request(end)。作者最初禁止unrelated和任何属性操作混合，这个取舍把结束生命周期错误地当作新增偏好，实际两阶段均attribute_mixed。不是供应商错误，也不支持“多一次分析自然会纠正”的推断。

修复仅允许有最新用户证据、空conditions/remove_attributes的end与unrelated组合，清本次RAM；新增/修改条件仍拒绝，品牌与确认的原混合守卫不变。新的实际回归先失败后通过；捕获的原最终响应只做离线decoder回放接受，重放时间明确是合成时间，不冒充再次真实结束或改善原分数。未重跑首测。

随后自审发现未知人物确认后预算会丢失，恢复推荐变成A/B/C，已用实际提问→确认→排名回归RED→GREEN修复。self/other确认都保留预算，available_at包含确认时间，证据引用包含原预算与实际确认；unclear继续保留待办。新增26项Python检查及1项Node提示输入检查。
