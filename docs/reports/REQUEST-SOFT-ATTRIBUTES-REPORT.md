## 行为

schema4 `attribute_changes`允许`scope=request`，仅`is_hard=false`；当前硬预算仍通过原`attribute_request`。
候选重新校验证据/数值/人物/时点，临时来源不借长期保存。本人和他人的临时软偏好均只依附当前选购任务，
不产生AttributeMemory，不升级为他人稳定会话偏好。无预算时可建立空条件任务，后续咨询/推荐沿用。
明确start/end、换推荐对象、fresh失效或重启清理；普通新消息本身不等于结束选购任务（临时反馈仍另按原规则结束）。

`active=false,value=null`表示该任务忽略指定属性全部软条件，由独立`soft_relaxations`进入排名，
不取消长期/当前硬预算，不改持久/稳定状态；结束后恢复。新长期同属性主动更新清除更早的临时软条件。
临时同属性覆盖全部旧软比较方向，硬预算优先过滤。四组共用同一当前要求，关闭长期记忆也不关本次要求。
仅RAM任务变化也推进宿主runtime revision，旧RPC回执失效；新RAM仅在commit成功后发布。

## 兼容与限制

不改持久schema；无request软偏好仍沿用旧行为。schema4新增scope枚举值，旧版本解码器不支持新值，不能仅看版本号断言可互读。
`soft_relaxations`正式工具/离线重放使用严格RequestRelaxation绑定，不能与同属性当前soft_preferences并存；
硬/软解除均新增本人属性删除水位校验。连续软信号仍复用0.75，未学习或校准最优权重/强度/置信度。
只有现有手机属性协议；模型可能仍误判自然语言边界，本轮没有实际供应商调用，不改旧冻结267/30调用结果或预留test。
单实例串行RAM，非跨进程会话数据库；不承诺外部日志/调用方副本的物理擦除。

完整目标仍待冻结最终一次语言/效用验收、预留test与整体独立终审；同品类自然语言+真实活跃画像效用证据仍不足。
当前不新增API授权、不训练下载、不推送；已消费预算不重新使用。
