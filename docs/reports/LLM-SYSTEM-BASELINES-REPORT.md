## 比较什么

`raw_history_llm`：给 LLM 当前请求及所有实际历史，让它直接返回目录内商品 ID。

`char_tfidf_user_turns_llm`：历史用户原文经 NFKC/casefold、字符1/2gram、logTF×smoothedIDF/cosine 检索 Top3，同分选最近；只索引用户，必要时附同一 session 紧邻的实际助手消息帮助解释短答，恢复时间顺序后给同一个 LLM。此为明确命名的词面检索系统，**没有语义 embedding，不是 Mem0 复现**。

两组使用相同 system prompt、实际 query、原始不透明商品 ID/顺序、合成目录事实和相同公共先验。无参考人物、预算、状态、eligible/relevance 输入。模型在这个独立研究入口可排序，但不能写记忆；生产 Pi 的商品 ID 顺序守卫及写入权限没有放宽。

对照锚点是原 direct G10（分析+Python记忆排名）实际结果。它逐轮处理并保存压缩记忆；完整历史组在查询时重读曾经历过的原文。原 analyst 的确认和前文已分化，不能当同一前缀的单变量控制，因此不拿它作本次锚点。此为系统比较，不能把差异全部归因于检索这一组件。

## 已确定的实验规范

最多30次 DeepSeek 客户端尝试，每任务两组各一次，整对预留预算，零重试。随机任务顺序、交替组先手8/7；相同官方客户端配置 deepseek-flash、temperature0、thinking disabled、JSON、max4096、每次30秒。首调前冻结输入、源码、预览和控制脚本；每次调用前后核对，发送前构造消息期间变更输入也必须停。只有显式live/环境Key/有限额度/新输出目录才能运行。

主分析：10个 provisional 任务、5个场景族，族内均值、族间等权；比较原锚点减完整历史、原锚点减检索两项 NDCG@3。1000次配对族 bootstrap 描述区间；包含5个 review 任务的15任务结果单列。检索减完整历史为次要对比，无多重比较校正，不外推真实用户满意度或所有传统记忆系统。

失败、无效ID、空列表保留分母；不合格商品 gain0，约束违反另报，无gain为N/A。解析错误仅本组记失败，继续另一组；供应商/元数据/冻结失败停止后续，保留未执行组，配对不完整不给区间。不会根据结果修标签或补跑。

成本必须分清历史构建与查询：原锚点完整生命周期89调用/348357token，其中查询15调用/59074token。新基线在查询时各最多15调用，其实际用量待供应商返回；不能将旧锚点一次查询与新基线全生命周期混比。旧新运行日期、缓存不同，不用延迟差作因果结论，不按profile零cost推算金额。
