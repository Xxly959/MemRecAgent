## 技术原理与完整例子

实际用户说“我一直讨厌小米”，第一阶段草案却只判为consult。可信调用方传入实际turns、已严格验证的草案和当前只读视图。独立角色重新读取原话，允许返回express_preference及本人long_term/dislike断言；返回值必须通过原文定位、实体、最新证据和人物结构检查，不能直接保存。新增固定响应测试验证了这条软件路径，但没有让DeepSeek实际选择此答案。

如果实际用户只是问“小米怎么样”，询问不能直接成为喜欢；如果他说的是母亲的喜好，不能授权读取/改写本人偏好。unknown或他人请求不被猜成本人。同轮有明确本人态度与他人请求时，仅本人态度相关实体可进入视图。

视图先检查整个输入的所有权、发生/可用时间和唯一当前头，再筛选phone、self、非neutral记录；时刻严格早于as_of。本人事实/线索/请求授权对应键；咨询/比较话题仅在明确self受益人时按精确键或一次末尾“手机”对齐。稳定排序后最多8条，证据摘录最多160个Unicode字符，原证据不修改，超出用truncated标明。直接构造视图与构造消息也执行相应边界检查，不能手工塞入无关本人记忆绕过筛选。

消息为新的system＋user(JSON数据)，没有user_id/session_id/snapshot_token专用字段；模型仍接收必要实际原话，不是自动匿名化。草案/旧记忆不能冒充新用户证据。最终确认除经过原decoder，还必须绑定实际pending_question；相邻/已可用的问题验证复用原消息构造器。

每次analyze最多调用注入complete一次；调用前拒绝为0次，调用后失败保留stage=analyst记录，没有重试或草案回退。账本保存调用前请求SHA256、安全错误码、明确选取的统计与供应商标识。usage转不可变元组；外部自由文本model/fingerprint不参与默认repr。显式序列化元数据仍由调用方处理，不称所有日志形式都匿名安全。
