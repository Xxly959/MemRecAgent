## 三种接法与推荐

| 方案 | 取舍 |
| --- | --- |
| 推荐：Pi Agent Core + 薄TypeScript适配 + 现有Python模块 | 复用工具循环，领域算法和记忆验证继续用Python；新增一个进程边界，需要明确消息、超时和会话契约 |
| 完整Pi coding-agent SDK/扩展 | 可复用更多会话/UI能力，但购物助手会额外承担编码资源、工具和默认会话语义，需要裁剪 |
| 深度fork Pi或把领域模块重写为TypeScript | 自由度高，但扩大维护、回归和实验变量；当前不建议 |

建议使用包依赖与适配，先不修改上游循环。Python工具后端优先本机受控子进程、JSONL请求/响应；是同一应用的运行适配，不增加远程微服务。现有推荐HTTP接口仍可独立复用，具体调用方式在实施规格中固定。Python进程持有user/session及存储，模型不能选择文件路径、身份或提交权限。写操作首版串行；工具ID去重、会话绑定、超时/中止、未知工具及预算终止均需可测试。

## 目标数据流（建议，未实现）

用户消息 → 现有意图/证据分析与会话状态 → Pi接收当前问题及相关背景 → 按需调用商品候选/事实与推荐工具 → Python计算分数/过滤结果 → Pi读取实际工具结果并生成解释 → 校验输出商品ID、引用及排序一致性。

一般闲聊不强行推荐或植入商品。写记忆由独立分析候选和宿主核验完成，不让普通回答中的判断自动写盘；本人/他人、范围、冲突和删除规则沿用。澄清问题必须确实向用户展示，不能由隐藏分析器虚构助手问句。只有本轮实际发送的助手消息才能进入后续确认语境。

建议只暴露领域能力：读取相关记忆、查看商品事实、获取候选、计算排序及提交已验证提案；具体工具签名未定。记忆读写的可信入口必须覆盖所有实验组，不能因自由工具调用而绕过控制。工具错误返回明确错误状态，不用模型补造数据。

例子：上一会话用户明确长期排除小米。新会话先聊晚饭，随后说“给我推荐手机”：仅此时按本人/手机检索；从同一冻结候选池按规则处理负偏好、预算与算法得分；解释实际排序原因。若改成“给我爸推荐，他喜欢小米”，本人排除不套到父亲。若说“这次就想看小米”，当前约束覆盖旧排除，本人长期记录不随之修改。上述为目标行为，不是现有自主Agent实测。

不能按国籍直接推断品牌偏好；预算、功能、品牌态度应依据实际表达/证据，未知时保留未知或必要澄清。

## 分层消融建议（未执行）

先固定同一Pi版本、模型配置、当前会话输入、候选ID/事实快照、基础推荐算法与输出格式。不同组使用独立用户存储；评测跨会话时，各组均清空旧聊天上下文，不能给无记忆组偷偷带入之前完整历史。当前用户明确约束各组同样可用。

| 组 | 处理 | 主要比较 |
| --- | --- | --- |
| M0 | 无跨会话偏好记忆，保留当前会话 | 无记忆基线 |
| M1 | 简单追加的文本偏好记忆，固定检索/输入上限 | M1−M0：简单持久记忆是否有用 |
| M2 | 带证据/人物/范围/修订与相关激活的记忆，仅供回答背景；基础排序不改 | M2−M1：整套记忆管理相对朴素记忆的贡献 |
| M3 | 与M2完全相同的提取/存储/检索，再把同一激活记忆显式用于过滤/排序 | M3−M2：显式推荐融合的贡献（包含过滤与排序，不称单独排序权重收益） |

M2−M1是组合干预，不能归因于某一个模块。随后只在完整方案上逐一关闭修订、对象隔离或相关激活，其他配置保持，定位组件贡献；过滤与软偏好加分也需分别去除才可区分作用。关闭安全规则仅限隔离合成实验，不用于真实用户。可增设手工正确记忆的诊断条件，区分提取失败与排序本身无效，不把理想记忆结果冒称实际系统收益。

测量分开：

- 记忆：提取/更新准确性、误写/漏记、本人/他人混淆、过时偏好、删除后再现。
- 行为：不该推荐时强推、必要/多余澄清、跨会话约束遵循、当前例外是否生效。
- 排名：有独立相关性标签时才算Recall/NDCG、负偏好冲突、列表多样性；保存工具排序和最终展示排序，解释须可回溯到实际分数/证据。
- 输出：事实引用支持率、无依据价格/规格、排名解释一致性；不能只用同一LLM给自己打分。
- 成本：所有物理模型请求（含分析器/失败/重试/评审）、token、延迟和终止原因。模型与每场景调用/token上限相同，实际用量分别报告；输入记忆长度不同，不能称实际token完全相同。

开发/冻结验收分离，失败仍留分母；不看验收答案继续调提示。排序重放用冻结相同候选以隔离记忆因素；自由工具使用的完整Agent再作为另一层端到端评测，保留实际工具轨迹及不同澄清分支，不强行把某组未来答案注入另一组。

现有真实数据是Amazon Musical_Instruments，手机品牌案例是合成记忆场景。不得将乐器模型当手机协同过滤模型。第一步可用有明确标签的合成手机目录验证机制，结果只能称合成任务效果；手机推荐收益还需核查真实目录及偏好/反馈数据的来源、许可、时间与独立标签。不能用本系统排序结果反过来生成答案证明自己有效。
