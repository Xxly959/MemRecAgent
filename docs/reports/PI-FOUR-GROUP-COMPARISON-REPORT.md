# 同一实际请求的 Pi 四组对照

> 公开整理版：保留工程方法、实验结果与失败记录；本机路径已泛化，教学和内部协作记录留在本地。原始数据、模型和运行日志不随仓库发布。

2026-10-24，Task3E。完整项目目标继续 active；本次交付排名组件对照和两故事机制首测，不代表整个研究已完成。

## 实现

`ConversationProductSession` 对每次成功推荐保存宿主生成的独立 request token，新用户轮次先使旧 token 失效；相同磁盘状态不代表仍是同一问题。`ConversationBridge` 新增 `comparison_binding`、`rank_current`、`check_comparison`：复用实际已接受的 query、人物、预算、会话偏好和历史，仅允许改变长期记忆开关及已有策略。读取前后核验 state 和 request token，缓存命中也重新核验。

分支不调用 MemoryAnalyst、不提交长期记录，不把反事实回答登记到共享历史。Node 的 `comparisonConnection` 关闭分支不关闭 owner，owner 统一清理；旧 RPC 和默认模式保持。

Pi 原来只在最终交付前核验快照，现在还在第二次主模型调用前核验，避免已删除或撤权的工具历史继续发送。验证晚到时重新检查取消、截止及调用预算；最终交付守卫及 ID 顺序检查仍执行。这是权限和新鲜度修复，不是模型语义准确率改善。

## 协议

目录 `artifacts/pi_comparison/20261024-live/` 的预注册、文字、目录、评分和 317 个源码/编译 JS/核心 SDK/锁文件等在首调前封存，终态哈希一致。无重试；旧 dev/test 及历史失败未改。输入由当前助手硬编码通用模板，作者知道标签，无独立人工标注或真实个人资料。

两个故事从空长期记忆开始：本人明确长期排除 A、喜欢 C，关闭 Python 并新建会话，再问预算三千的手机推荐；叔叔喜欢 C、本人没有品牌倾向，在同一会话给叔叔选预算三千的手机。合成价格 A4000/B2500/C2000，热度 10/9/8。已有固定向量只保存、不训练；两个用户都不在模型画像内。

每故事先实际 Pi 前置轮次，再正常推荐 G11，随后三个只读分支复用 G11 的分析和前文，不重复跑 G11。主模型及 Python 分析都是真实 DeepSeek，最终 ID 按程序顺序展示。只将实际生成的 prefix 和选定 G11 保存到应用交付记录后 observe，反事实分支不追加。四条记录是受控应用历史，不是四次真实用户消费或满意度证据。G11 固定先执行，其他分支固定次序，延迟和缓存不作因果比较。

上限及实际均为主模型 20 次、分析 8 次，共 **28 次**；20 次主模型 HTTP 均 200，8 次分析适配调用均成功返回 deepseek-flash。主模型 13,375 token、分析 34,550 token，共 **47,925**，未知用量 0。共享分析只计一次；没有用模型 profile 的零 cost 推断金额。

## 结果

| 故事 | G00：热度/关长期 | G10：热度/开长期 | G01：算法策略/关长期 | G11：算法策略/开长期 |
| --- | --- | --- | --- | --- |
| 本人跨会话 | B→C | C→B | B→C | C→B |
| 给叔叔推荐 | C→B | C→B | C→B | C→B |

8/8 组成功推荐且顺序符合预声明的合成预期，均有同一三千预算，均未返回 A。同故事四组的实际历史、相关偏好视图和状态 token 一致。只读分支的分析调用和新记录 ID 为空，磁盘前后摘要不变。

本人实际保存 A exclude、C prefer 两条记录，证据分别为最小原文片段，关闭/重开后文件摘要一致。叔叔故事长期记录 0，C 信号来自同一会话；未将他人偏好写成本人。跨会话例未观察到长期预算写入。

预声明 Cgrade3/Bgrade1 的 NDCG@2 两故事均值：G00/G01 为 0.854905，G10/G11 为 1.000000。两个作者机制例不作统计外推；预算本身也排除了 A，不能单独识别排除记忆的价值。软 C 偏好导致本人顺序变化，他人组相同是会话偏好始终保留的预期。

**全部实际 used_strategy=popularity**：本人冷用户回退，叔叔按非本人公共底座路由。算法和协同效应记 null，不能将 G01/G11 名称当 MF/BPR 生效。关长期只改变排名读取，模型仍看到相同历史/上下文，因此也不等于整个 Agent 无记忆的系统基线。
